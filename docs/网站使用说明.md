# 志愿云时长录入助手（网站版）

一个跑在**你自己电脑上**的网页工具：把名单变成可直接粘贴到志愿云的录入模板。

**不联网、不登录志愿云、不代替你提交。** 所有数据只在本机内存里处理。

---

## 启动

```bash
git clone https://github.com/qiu-free/zhiyuanyun-hour.git
cd zhiyuanyun-hour
npm install
npm run web
```

看到这个就成功了：

```
  志愿云时长录入助手已启动
  ────────────────────────────────────────
  打开浏览器访问：http://127.0.0.1:5180

  按 Ctrl+C 停止
```

然后用浏览器打开 **http://127.0.0.1:5180**。

> 端口被占用时换一个：
> ```bash
> set PORT=5181 && npm run web
> ```

## 怎么用

### 第一步：把名单给它

两种方式，页面上切换标签：

**① 粘贴文本**（推荐，最省事）

格式随意，混着来也行：

```
张三 2025213817 110101200501010017 8
李四，2024213884，110101200502020022，8小时
姓名：王五 学号：2025213761 身份证：110101200503030038 时长：8
赵六|2024213879|110101200504040043|8
```

支持空格、中英文逗号、竖线、带标签等写法；
标题行、空行、`合计 5 人` 这类汇总行会**自动跳过**。

### 没有换行也能用（从 Word 复制常遇到）

从 Word / 微信复制时，**换行经常丢失**，整段挤成一行。这种情况也能处理：

```
各位同学，现将补录名单公布如下 张三 110101200501010017 8 数学学院 李四 110101200502020022 12 统计学院 请大家核对
```

程序会**按身份证号定位，自动拆成 3 个人**，并在页面上明确告诉你：

```
✂️ 检测到 1 行没有换行，已自动拆成 3 人
   第 1 行 → 3 人
   请核对下表人名和时长是否对应正确
```

**为什么能拆准**：身份证号格式固定、每人唯一，是全行最可靠的锚点。
程序把它当"桩"，再把姓名和时长按就近原则分配——姓名优先取锚点**前面**的
（因为「姓名 身份证 时长」和「姓名 时长 身份证」两种写法里，姓名都在自己身份证前面）。

**多出来的内容不会捣乱**。下面这些都能正确忽略：

| 输入 | 处理 |
|---|---|
| 班级、学院、专业、年级 | 忽略 |
| 电话 `13800138000` | 忽略（不会被当成学号） |
| 序号 `1` `2` `3` | 忽略（不会被当成时长） |
| 开头"各位同学…"、结尾"请大家核对" | 忽略 |

**但请务必核对拆分结果**。拆分靠位置推断，如果原文写得特别含糊，
可能配错人。页面上会给出每人的还原片段供你核对：

```
张三 110101200501010017 8
李四 110101200502020022 12
```

发现配对错了，直接在表格里改，或回原文每行加个换行重新粘。

> ⚠️ **早期版本在这里有个严重缺陷**：没有换行时只识别第一个人，
> 后面的人被静默丢弃，界面上还显示成功。现在已修复，
> 并且有 59 项自检专门锁住这个场景。

**② 上传 Excel**

把 .xlsx 拖进去即可。需要包含列：`姓名`、`身份证号`、`志愿时长`（`备注`、`学号` 可选）。

表格上方有标题行没关系，程序会自动找真正的表头。

> 关于 Word 文件：不需要上传 `.docx`。你从 Word 里 Ctrl+C、再粘到输入框就行，
> 上面的"没有换行也能用"正是为这条路准备的。

### 第二步：填「统一补录原因」

这是系统必填项，会写进志愿者档案。

- 名单里已经写了备注（如 `备注：xxx`），这里可以不填
- 名单里没写，就必须在这里填，或者之后在表格里逐条补

**留空且名单里也没写时，这些行会被标成「待报备」——程序不会替你编一个原因。**

### 第三步：核对与修正

点「开始处理」后，你会看到：

- **统计卡片**：左边两个大数字 ＝「可以录入」和「需要处理」，右边小字是明细
- **提示条**：告诉你该做什么（去问发起人 / 去改哪一格）
- **结果表格**：每条一行，可以直接点进去改

**表格里的四种底色**（页面上也有图例，不用记）：

| 底色 | 含义 | 你要做的 |
|---|---|---|
| 🔴 红底 | 数据有错 | 点那一格直接改 |
| 🟡 黄底 | 缺补录原因 | 去问发起人 |
| 🟣 紫底 | 时长超 50 小时 | 正常，走「分批录入」 |
| 🔵 蓝底 | 能录入，但有提示 | 看一眼，通常不用改 |

**状态标签**：

| 标签 | 含义 | 能否导出 |
|---|---|---|
| ● 可用 | 没问题 | ✅ |
| ! 待确认 | 有小提示（如 15 位老身份证） | ✅ **仍可导出** |
| ⇄ 需分批 | 时长超 50 小时，要分多次录 | ✅ **可导出，但走分批面板** |
| ▲ 待报备 | 缺补录原因 | ❌ |
| ✕ 有问题 | 数据错误 | ❌ |

> 「需分批」不是错误。数据本身没问题，只是系统单次最多录 50 小时，
> 得分几次。详见下面「时长的限制」。

> 「原文行号」列是你原始文本/Excel 里的实际行号。
> 如果跳号（如 3 之后直接是 5），说明第 4 行被自动跳过了——
> 展开下方「已跳过的行」可以看到原因。

表格里能做的：

| 操作 | 说明 |
|---|---|
| 改姓名 / 身份证 / 时长 / 备注 | 点进去直接编辑，改完立刻重新校验 |
| 删掉某条 | 点最右边的 ✕ |
| 看提示 | 显示在出问题的那一列下方 |

改过的行，行号前会出现一个蓝色小点（`·`），方便你分辨哪些是原始数据。

**改完不需要滚回顶部**——「核对与修正」标题右边就有一个「复制粘贴文本」按钮。

### 第四步：导出

四种方式：

| 按钮 | 用途 |
|---|---|
| **复制粘贴文本** | 直接进剪贴板，到后台 `Ctrl+V` |
| 下载 .txt | 存成文件 |
| 下载 Excel | 含「录入模板」+「核对表」两个工作表 |
| 查看时间锁排期 | 有人时长超 50 小时时看分批安排 |

页面下方会实时显示**粘贴文本预览**，格式是：

```
姓名,身份证号,时长,备注
```

## 时长的限制：一次能录多少、要等多久

### 三条硬规则

| 规则 | 数值 | 说明 |
|---|---|---|
| **单次上限** | 50 小时 | 一次最多录 50 小时，超过要分多次 |
| **等待时间** | 24 ~ 120 小时 | 录完后**同一人在同一项目**要等系统解锁才能再录 |
| **最小粒度** | 0.1 小时 | 可以录 8.5 小时 |

> 等待时间只影响**同一个人**。张三录完后要等，但李四不受影响，
> 可以同一天接着录。

### 录多少 → 等多久

| 单次录入时长 | 下次可录入需等待 | 举例 |
|---|---|---|
| ≤ 10 小时 | 24 小时（1 天） | 录 8 小时 → 明天可再录 |
| 10 ~ 20 小时 | 48 小时（2 天） | 录 15 小时 → 后天可再录 |
| 20 ~ 30 小时 | 72 小时（3 天） | 录 25 小时 → 3 天后可再录 |
| 30 ~ 40 小时 | 96 小时（4 天） | 录 35 小时 → 4 天后可再录 |
| 40 ~ 50 小时 | 120 小时（5 天） | 录 50 小时 → 5 天后可再录 |

### 超过 50 小时怎么办

**两种办法，各有代价，你自己选：**

| 办法 | 做法 | 代价 |
|---|---|---|
| **A. 原地分批** | 在同一个项目里分几次录 | 要等 24~120 小时 |
| **B. 换项目分流** | 把时长分到 2~3 个不同项目 | 要真有那么多项目；记录会分散 |

#### 办法 A：原地分批（默认方案）

| 某人总时长 | 怎么分 | 录完约需 |
|---|---|---|
| 40 小时 | 一次录完 | — |
| 50 小时 | 一次录完（正好到上限） | — |
| 51 小时 | 50 + 1 | 5 天后 |
| 80 小时 | 50 + 30 | 5 天后 |
| 100 小时 | 50 + 50 | 5 天后 |
| 120 小时 | 50 + 50 + 20 | 10 天后 |

**为什么每次尽量录满 50**：录得越多等得越久，但批次更少，
总的等待时间反倒最短。比如 120 小时 `50+50+20` 等 10 天；
改成每次 10 小时要等 11 次共 264 小时（11 天），操作次数还多一倍。

#### 办法 B：换项目分流（大幅提速）

**原理**：时间锁是「**同一人在同一项目**」的限制。把时长分到不同项目，
两边**互不等待**；配合少量等待，就能把完成时间砍掉一大半。
志愿者总时长照常累计。

**这两种办法可以同时用**——不是二选一。工具会自动算最优组合。

**效果（以 120 小时的人为例）**：

| 你有几个项目 | 怎么安排 | 完成时间 |
|---|---|---|
| 1 个 | 50 → 等 5 天 → 50 → 等 5 天 → 20 | 10 天 |
| 2 个 | 项目1 录 50、项目2 录 50（当天）<br>→ 等 5 天 → 项目1 再录 20 | **5 天** |
| 3 个 | 项目1 录 50、项目2 录 50、项目3 录 20 | **当天** |

**规律：每 50 小时需要一个项目，才能当天录完。**

**为什么 2 个项目是 5 天而不是 10 天**：两个项目当天各录 50（共 100 小时），
还剩 20 小时等 5 天后录。这是"换项目"和"等待"**一起用**的结果——
比只用 1 个项目快一半。

点「→ 换项目分流」，填上你实际有几个项目，工具会算出：
- 每个人分到哪个项目、每次录多少
- 每个项目要贴的完整文本（一键复制）
- 操作顺序（哪些今天做、哪些几天后做）

**但要先想清楚这两条代价**：

1. **志愿者的记录会分散。** 同一个人会在多个项目里各有一条记录，
   他查看自己的服务记录时会看到多条，而不是一条总计。
2. **项目属性会影响时长归集。** 如果学院对"什么算志愿服务"有要求，
   拆分可能让某些时长落在一个不太合适的项目名下。**建议先问一下发起人。**

### ⚠️ 一个重要澄清：「当天录完」≠「一次粘贴」

这点容易搞混，而且搞混了会导致操作失败：

**50 小时是「每人每次」的硬限制**，跟你有多少项目**完全无关**。
项目多只能让这些提交**都在同一天做完**，不能把 120 小时变成一次提交。

| 某人总时长 | 最少要提交几次 |
|---|---|
| ≤ 50 小时 | 1 次 |
| 51 ~ 100 小时 | 2 次 |
| 101 ~ 150 小时 | 3 次 |
| 151 ~ 200 小时 | 4 次 |

规律：**`ceil(总时长 ÷ 50)` = 最少提交次数**。

所以正确理解是：
- ✅ 项目足够多 → 所有提交**都在今天**完成，不用隔几天
- ❌ 项目足够多 → ~~把 120 小时一次粘进去~~ （后台会拒绝，因为单条超 50）

面板上会明确写出这一点，并告诉你每个人要提交几次。

> **工具不会硬塞**：如果项目不够，绝不会生成超过 50 小时的录入值，
> 而是把「能当天录的」和「要等的」分开算清楚。

## 备注怎么写都能认

备注是**系统必填**，工具认这三种写法：

| 写法 | 例子 |
|---|---|
| **第 4 列直接写**（最常用） | `张三<TAB>110101...<TAB>1小时<TAB>2025.12.9参加"三清"活动` |
| 带标签 | `张三 110101... 1小时 备注：2025.12.9参加"三清"活动` |
| 统一填 | 上面「统一补录原因」填一次，所有人共用 |

分隔符用**制表符、空格、逗号都行**。

**时长带不带单位都行**：`1小时` 和 `1` 都能认。
备注里出现 `2025.12.9下午3：00到4：00` 这种日期时间，工具会自动跳过它们，
不会把里面的 `3`、`4` 误当成时长。

> **早期版本的坑**：只认「备注：xxx」这种带标签的写法，
> 第 4 列直接写的备注会被整段丢掉。备注一丢，所有行都变成「待报备」，
> 于是复制按钮没有任何内容可复制 —— 看起来就像"点了没反应"。
> 现在两种写法都支持。

## 身份证号位数不对

如果身份证号不是 18 位（多打、少打都常见），工具会**明确告诉你读到几位**：

```
测试同学  身份证号位数不对：读到 19 位，应为 18 位
```

这一行的**姓名、时长、备注都会保留**，只有身份证号需要你补正。
改完点「重新输入」或直接在表格里改。

> 注意：那串错误号码**不会**跑进备注里。
> 早期版本会把它当成备注文字，导致备注变成一串数字。

### 工具怎么帮你

只要有人超过 50 小时，页面会出现两块东西：

**① 提示条**——告诉你谁超了、分几次、每次录多少：

```
⏳ 2 人的时长超过 50 小时，一次录不完
姓名   总时长   需录   各次时长          录完约需
张三   80 小时  2 次   50h + 30h        5 天后
王五   120 小时 3 次   50h + 50h + 20h  10 天后
```

**② 分批面板**（点「生成分批录入文本」）——**每一轮给你一段现成的粘贴文本**：

```
第 1 轮  现在可以录 · 3 人 · 合计 108h
  李四,110101200502020022,8,迎新
  张三,110101200501010017,50,全年服务
  王五,110101200503030038,50,支教
  [复制这一轮]

第 2 轮  5 天后可以录 · 2 人 · 合计 80h
  张三,110101200501010017,30,全年服务
  王五,110101200503030038,50,支教
  [复制这一轮]

第 3 轮  10 天后可以录 · 1 人 · 合计 20h
  王五,110101200503030038,20,支教
  [复制这一轮]
```

第 1 轮顺便把「一次就能录完的人」也带上了（反正他们不受等待限制），
所以你照着轮次走就行，不用自己在两处之间拼。

### 两点注意

1. **主「复制粘贴文本」里不含超限的人**。他们没法一条粘完，硬粘会被后台拒绝
   或录错。请走上面的分批面板。
2. **第 2 轮之后要等够时间再录**。面板上标的「5 天后」是系统解锁的最早时间，
   提前录会失败——不是工具的问题。

## 时间锁排期（详细版）

点「查看时间锁排期」会给出更细的排期表，还能切换两种策略：

- **每批尽量大**（默认）—— 等待时间最短，通常也是批次最少的
- **每批 ≤10 小时** —— 批次多，但每批锁得短；只有「不想单批录太多」时才用

> 两种策略的实际耗时对比，排期页会当场算给你看。

## 关于分隔符的坑

粘贴文本用**英文逗号**分隔。所以**备注里不能再有英文逗号**。

如果备注写成 `迎新,社区清扫`，后台会把这一行切成 5 段，
导致时长被当成备注、备注被吃进下一列——**可能录到错的人身上**。

工具会把这类行标成「有问题」并指出原因。改掉即可（把逗号换成顿号「、」）。

### 隐私检查怎么做的

`scripts/check-privacy.js` 长期防止真实个人信息被写进项目：

- 真实姓名和身份证号**只以 SHA-256 哈希形式保存**，仓库里没有明文
- 姓名按「中文词元」扫描后比对哈希；证号按 **15~20 位**扫描
  （只查 18 位会漏掉打错位数的号码）
- 不在白名单里的长号码一律报警，退出码 1

> **为什么按 15~20 位**：真实数据最常见的错误是多一位或少一位。
> 曾经有一行写成 19 位，只查 18 位就漏过去了。

## 界面设计说明

界面经过一轮 UI 评审并调整，几处关键改动：

**状态从三档改成四档。** 原来「能导出但有提示」的行（如 15 位老身份证）
显示成绿色「可用」，却在输入框画了红框、备注列写红字——自相矛盾。
现在独立成蓝色「待确认」，明确它**仍然可以导出**。

**统计卡分层。** 原来 5 张等重卡片，「合计小时」和「有问题」一样显眼。
现在左边两个大数字是「可以录入 / 需要处理」，其余是小字明细。

**问题提示落到对应列。** 原来所有问题都挤在备注列下面，
身份证错了却在备注格里提示。现在挂到出问题的那一列。

**间距统一刻度。** 原来间距有 2/3/5/6/9/14/18/22 等十来个随手值，
现在收敛到 4px 基准的 7 个值，同类元素间距一致。

**保留原有的视觉语言**：白底卡片、蓝色主色、圆角、语义三色都没有换，
只是把层级、间距和状态表达理清楚了。

## 常见问题

**Q：为什么打不开网页？**

先确认 `npm run web` 那个窗口还开着（关掉窗口服务就停了）。
端口被占用就换一个：`set PORT=5181 && npm run web`。

**Q：粘贴文本里为什么有完整身份证号？**

因为后台要靠它匹配志愿者，必须完整。页面上的预览是打码的，
但你点「复制粘贴文本」时复制的内容是完整的——这是必要的。

**Q：能不能直接帮我提交到志愿云？**

不能，也不打算做。本工具只生成文本，需要你自己到后台粘贴。
这样你始终能看到将要提交的内容，也保留了最后确认的机会。

**Q：Excel 里身份证显示成 1.10101E+17？**

那是 Excel 把它当数字了，精度已经丢失。回原表把该列设成「文本」重新导出。
工具会检测到这个情况并报错提示。
