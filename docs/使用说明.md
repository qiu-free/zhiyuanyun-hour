# 使用说明

从零开始的完整操作流程。全程大约 10 分钟。

---

## 第 0 步：这套流程在做什么

后台有**批量导入**入口，方式是**把文本粘贴进一个输入框**。

所以整个流程就是：

```
你的表格  →  校验数据  →  生成粘贴文本  →  你复制到后台粘贴
```

本工具负责**前三步**，最后一步由你亲手完成。
**它不登录、不提交**，你始终能看到将要提交的内容。

### 粘贴格式（已确认）

每人一行，**英文逗号**分隔，四列依次为：

```
姓名,身份证号,时长,备注
张三,110101200501011239,8,2025年迎新志愿服务
李四,130102200503152342,12.5,社区环境卫生清扫
```

> ⚠️ 因为用英文逗号分隔，**备注里不能再有英文逗号**，
> 否则这一行会被切成 5 段，列全部错位。
> 工具会拦下这种行，详见「第 4 步」。

## 第 1 步：安装

```bash
git clone https://github.com/qiu-free/zhiyuanyun-hour.git
cd zhiyuanyun-hour
npm install
```

用 pnpm 的话：

```bash
pnpm install --node-linker=hoisted
```

> **`--node-linker=hoisted` 建议加上。**
> pnpm 默认用符号链接隔离依赖，部分环境下会导致模块解析失败
> （`ERR_MODULE_NOT_FOUND`）。加这个参数会改用扁平结构。
> 项目里的 `.npmrc` 已经写了这个配置。

### 验证安装是否成功

```bash
npm test
```

看到全部 `✓` 且最后没有报错，就说明环境正常。

## 第 2 步：准备你的表格

在 `data/` 目录放一个 Excel 或 CSV，需要这些列：

| 姓名 | 学号 | 身份证号 | 志愿时长 | 备注 |
|---|---|---|---|---|
| 张三 | 20230101 | 110101200501011234 | 8 | 2025年迎新志愿服务 |
| 李四 | 20230102 | 110101200502022345 | 12.5 | 社区清扫 |

**列名要求**

- 中文表头：`姓名` / `学号` / `身份证号` / `志愿时长` / `备注`
- 英文表头：`name` / `studentId` / `idCard` / `hours` / `remark`
- 大小写、空格、`*` 号都不影响识别

**注意**

- 表格上方有标题行、说明行没关系，程序会自动找到真正的表头行
- **身份证号列在 Excel 里要设成「文本」格式**，否则 18 位数字会变成 `1.10101E+17`，精度丢失后无法恢复
- 学号可有可无（系统不认学号，只用于你们内部核对）
- **备注即系统的「补录原因」，是必填项**。缺失时程序不会代填，而是提示你向发起人报备（见下）

### 关于缺失信息：程序不猜，一律报备

「补录原因」会写进志愿者的档案记录，属于业务事实，**必须由发起人确认**。

如果表格里没有「备注」列（或某几行备注为空），程序会**停下来**，
列出缺哪些人、缺什么，并告诉你去问什么：

```
🚩 有 9 行缺少「补录原因」，需要向发起人报备：

  「补录原因」是系统必填项，且会写进志愿者的档案记录。
  程序不代为填写，请先向发起人确认后再补上。

  行号      姓名          学号            时长
  ──────────────────────────────────────────────
  第2行     张三          2025213817    8
  第3行     李四          2024213884    8
  ...

  ✅ 请向发起人确认：
     • 本次补录的原因 / 活动名称是什么？
     • 是否所有人员用同一个原因？还是因人而异？

  ✅ 拿到答复后，二选一：
     1. 回表格里加一列「备注」，逐人填写，然后重新运行
     2. 若所有人原因相同，直接用参数指定：
        npm run paste -- --file "..." --reason "你们确认的原因"
```

此时**退出码为 4**，且**不会复制到剪贴板**（避免你粘贴到残缺数据）。

> 这条规则适用于所有缺失项：缺什么就报什么，不会用默认值糊过去。
> `.env` 里的 `ZY_DEFAULT_REASON` 也默认为空，就是为此。

想先拿假数据试跑：

```bash
node scripts/make-sample.js
```

会在 `data/sample-volunteers.xlsx` 生成一份含各种错误的样例。

## 第 3 步：校验数据（必做）

```bash
npm run validate -- --file data/volunteers.xlsx
```

会输出：

```
── 校验结果 ──────────────────────────────
  总行数      14
  通过        8
  有问题      6
  合计时长    123 小时
──────────────────────────────────────────
```

并生成完整报告 `output/xxx-report.md`。

### 会检查什么

| 检查项 | 说明 |
|---|---|
| 身份证校验位 | 用 GB 11643-1999 算法验算，错一位就报错 |
| 出生日期合理性 | 比如 `20050230` 这种不存在的日期会被拦下 |
| 时长格式 | 支持 `8`、`12.5`、`15小时`，拒绝文字和负数 |
| 单次上限 | 超过 50 小时会提示需拆分 |
| 重复人员 | 同一身份证出现两次 → 报错；同名不同证 → 提示 |
| 姓名异常 | 空姓名、含数字、含奇怪字符 |
| 备注长度 | 超过 200 字会报错 |

**有 ❌ 就不要往下走**，回 Excel 改完重新校验。

---

## 第 4 步：生成可粘贴文本

```bash
npm run paste -- --file data/volunteers.xlsx --clip
```

`--clip` 会把文本直接放进剪贴板。然后：

1. 登录志愿云后台 → 我的项目 → 找到项目的「记时」/「批量录入」入口
2. 在输入框里 `Ctrl+V`
3. 确认导入结果

产物：

| 文件 | 用途 |
|---|---|
| `output/*-paste.txt` | 要粘贴的文本（也可以直接打开复制） |
| `output/*-核对表.md` | 含学号，供学院内部核对人数和时长 |

控制台预览会把身份证打码，但**剪贴板里是完整号码**（粘贴需要）。

### 备注含英文逗号怎么办

工具会拦下并报错：

```
❌ 有 3 行无法生成（会破坏列结构）：
  第3行 李四
      • 备注中含英文逗号：迎新,社区清扫
        建议：把逗号换成顿号「、」或分号「;」
```

二选一：

```bash
# 办法一：回表格把备注里的逗号改成「、」，重新运行
npm run paste -- --file data/volunteers.xlsx --clip

# 办法二：让工具自动替换（会改动备注文字，请确认可接受）
npm run paste -- --file data/volunteers.xlsx --fix --clip
```

被拦下时退出码为 `3`，且会明确告诉你少录了几个人——
不要粘完就以为完事了，先处理被拦下的行。

### 其他会被拦下的情况

| 情况 | 原因 |
|---|---|
| 备注含换行 | 会被当成新的一行 |
| 备注含制表符 | 可能被当成分隔符 |
| 姓名含逗号 | 同样会串列 |
| 时长写成 `5小时` | 后台要纯数字 |

## 常见问题

### 提示「在项目志愿者列表中找不到 XXX」

- 该志愿者**还没报名加入这个项目**。先在后台把人加进项目，再录时长。
- 这是后台的提示，不是本工具的。工具只负责生成文本。

### 提示「触发时间锁」

- 该志愿者此前已在本项目录过时长，且未到间隔时间。按提示等待即可。
- 用 `npm run schedule` 可以提前规划，避免撞锁。
- 详见 [网站使用说明](网站使用说明.md) 里的「换项目分流」。

### 身份证号显示成 `1.10101E+17`

- Excel 把它当数字了，**精度已丢失，无法挽回**。
- 回原表把该列设为「文本」，重新输入或从原始数据源重新导出。
- 判断方法：如果原始数字超过 15 位，Excel 默认就会这么干。

### CSV 打开是乱码

- Excel 打开 UTF-8 的 CSV 会乱码。用「数据 → 从文本/CSV」导入，选 UTF-8 编码。
- 或者干脆用 `.xlsx`，不会有这个问题。

### 表格里有多个工作表

- 工具会**自动跳到第一个有内容的工作表**，跳过封面/说明页。
- 想指定工作表用 `--sheet`：

```bash
npm run validate -- --file data/volunteers.xlsx --sheet 名单
```

### 上传后想撤回

- 网站界面上的「取消选择」退回未选择状态，「清空全部」清空所有数据。
- 这两个按钮**只清本工具的界面**，不影响任何已提交到平台的数据。

## 命令速查

```bash
# ===== 生成可粘贴文本 =====

# 校验（必做）
npm run validate -- --file data/volunteers.xlsx

# 生成并复制到剪贴板
npm run paste -- --file data/volunteers.xlsx --clip

# 备注里有英文逗号时，自动替换
npm run paste -- --file data/volunteers.xlsx --fix --clip

# ===== 其他 =====

# 启动网站界面（推荐）
npm run web

# 查看时间锁排期
npm run schedule -- --file data/volunteers.xlsx

# 生成 xlsx 导入模板（若后台支持上传文件）
npm run template -- --file data/volunteers.xlsx

# 生成样例数据（含各种故意埋的错，用来试跑）
npm run sample

# ===== 自检 =====

npm test              # 全部自检（隐私 + 9 组，600+ 项）
npm run test:web      # 后端接口自检（需先 npm run web）
npm run privacy       # 只跑隐私检查
```

### 退出码含义

| 退出码 | 含义 |
|---|---|
| `0` | 全部成功 |
| `1` | 参数或配置错误（如缺 `--file`） |
| `2` | 数据校验未通过，或没有可处理的数据 |
| `3` | 部分行数据有问题（如备注含逗号），只生成了部分数据 |
| `4` | **有缺失信息待报备**（如缺补录原因），未生成对应行 |

## 还需要你自己确认的一件事

本工具已验证的部分：文本解析、多人拆分、Excel 读取、分批排期、
粘贴文本往返一致性、隐私检查（共 600+ 项自检）。

**但有一件事工具无法代你验证**：

> 后台的粘贴输入框能否正确解析 `姓名,身份证号,时长,备注`
> 这种英文逗号格式。

这必须在真实后台里试一次。建议先拿 **1～2 条**数据试粘，
确认列对得上、时长认得出来，再粘完整的名单。

如果格式不对，可以用 `--fix` 调整分隔符，或回表格修改后重新生成。

被拦下的行**会明确报出来，不会静默跳过**——这是刻意设计，
避免「以为录上了其实没录」。看到退出码 `3` 或 `4` 时，
先处理被拦下的名单，再粘已完成的部分。
