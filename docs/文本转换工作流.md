# 工作流：任意文本 → 志愿云录入模板

**一句话**：把名单文本（随便什么格式）给我，我返回可直接粘贴到志愿云的模板。

**完全不碰平台** —— 不登录、不联网、不添加任何数据。只在本机做文本转换。

---

## 用法

```bash
cd zhiyuanyun-hour
```

### 方式一：直接给文本

```bash
npm run text -- --text "张三 110101200501010017 8" --reason "暑期迎新志愿服务活动"
```

### 方式二：给一个 txt 文件（推荐）

```bash
npm run text -- --file data/名单.txt --reason "暑期迎新志愿服务活动" --clip
```

`--clip` 会把结果直接放进剪贴板，然后到后台 `Ctrl+V` 就完了。

### 方式三：管道

```bash
type 名单.txt | npm run text -- --stdin --reason "暑期迎新志愿服务活动"
```

## 输入：什么格式都能认

下面这些**混在一起**也能正确识别：

```
暑期迎新志愿服务名单

张三 2025213817 110101200501010017 8
李四，2024213884，110101200502020022，8小时
姓名：王五 学号：2025213761 身份证：110101200501010017 时长：8

赵六|2024213879|110101200503030038|8|迎新服务
孙八 2023213829 110101200505050059 12.5小时
```

已验证支持：

| 分隔方式 | 例子 |
|---|---|
| 空格 | `张三 110101200501010017 8` |
| 中文逗号 | `李四，110101200502020022，8小时` |
| 英文逗号 | `李四,110101200502020022,8` |
| 竖线 | `赵六\|110101200503030038\|8` |
| 带标签 | `姓名：王五 身份证：... 时长：8` |
| 时长带单位 | `8小时` `8h` `12.5小时` |
| 时长无单位 | `8` |
| 时长在前 | `8h 钱七 110101200501010017` |
| 带备注 | `赵六 ... 8 备注：迎新服务` |

**会自动跳过**：标题行、空行、`合计 8 人` 这类汇总行、表头行。

## 输出

### 1. 粘贴模板（`output/*-模板.txt`）

```
张三,110101200501010017,8,暑期迎新志愿服务活动
李四,110101200502020022,8,暑期迎新志愿服务活动
...
```

**格式**：每人一行，英文逗号分隔，四列依次 `姓名,身份证号,时长,备注`。

### 2. 核对表（`output/*-核对表.md`）

含逐条明细（身份证打码），用来核对人数和时长，以及**哪些行没被采纳、为什么**。

---

## 两条硬性规则

### 规则一：缺「补录原因」就停下报备，程序不代填

「补录原因」是系统必填项，会写进志愿者档案。如果输入文本里没有备注，
程序会列出缺哪些人，并让你去问发起人：

```
🚩 8 条缺少「补录原因」，需要向发起人报备：

  行号      姓名          时长
  ──────────────────────────────────
  第3行     张三          8
  第4行     李四          8
  ...

  ✅ 请向发起人确认后，二选一：
     1. 在文本里加一行「补录原因：xxx」
     2. 所有人原因相同时，加参数：--reason "你们确认的原因"
```

此时 **exit=4**，且**不复制到剪贴板**（避免你粘到残缺数据）。

### 规则二：抽不准就报错，绝不猜

比如身份证打码了、校验位错了、时长认不出，都会**明确报出来**并跳过该行，
不会瞎填一个值让你录错人。

---

## 退出码

| 码 | 含义 |
|---|---|
| `0` | 全部成功 |
| `1` | 参数错误（没给输入） |
| `2` | 有数据错误（身份证、时长、备注含逗号等） |
| `4` | 有缺失信息待报备（缺补录原因） |

## 常见问题

**Q：为什么不用原来的 Excel 路线了？**

Excel 路线（`npm run paste`）也能用，但要求表格有规范表头。
这条文本路线更宽松——你从微信、QQ、聊天记录里直接复制过来就能用。

**Q：身份证号必须完整吗？**

必须。打码的（`500113********9196`）会被判为不可用并报出来，
因为系统要靠完整号码匹配志愿者。

**Q：能不能不写备注？**

不行。这是系统必填项。要么写在文本里（`备注：xxx` 或开头写 `补录原因：xxx`），
要么用 `--reason` 统一指定。

**Q：会不会自动帮我添加？**

不会。这条工作流只做文本转换，产物是一个 txt 文件/剪贴板内容，
需要你自己到后台粘贴。
