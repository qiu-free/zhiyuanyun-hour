# 为什么这个工具不做「自动提交」

## 一句话

**这个工具只生成文本，由你亲手粘贴。这是刻意的设计选择，不是没做完。**

---

## 三个理由

### 1. 你看得见将要提交的内容

自动提交最大的问题是**你看不到中间过程**。工具替你点了几十下，
其中一行录错了、时长填反了、串到了同名的人身上——你事后很难发现。

粘贴方案里，文本先在屏幕上显示出来，你核对过再按 `Ctrl+V`。
出错的话，你**在提交前**就看见了。

对于记录进他人档案的数据，「能核对」比「省事」重要得多。

### 2. 批量粘贴本来就比逐条点击快

后台支持把多行文本一次贴进去。9 个人一次贴完，
比自动逐个搜索、填时长、点提交要快。

自动化的优势在「几百条」，而这个场景的批量通常是几十条。
为几十条引入浏览器驱动、登录会话、验证码处理，收益不划算。

### 3. 不碰账号就不承担账号的责任

工具一旦登录，就意味着：

- 你的账号密码要经过工具（或被存在某处）
- 平台侧看到的操作全部来自你的账号
- 出现异常时，责任边界变得模糊

不登录，这些问题都不存在。工具只是把 Excel 变成文本，
剩下的每一步都由你自己完成。

## 关于 RSA 加密登录（已实现的探测结论）

早期确实探测过登录流程，结论记录如下（**代码已从项目中移除**）：

| 项 | 结论 |
|---|---|
| 登录入口 | `/app/user/login.php`，表单提交到 `?m=login` |
| 密码加密 | RSA PKCS#1 v1.5 / 1024 位 |
| 公钥位置 | `css.zhiyuanyun.com/common/login.js` |
| 防护 | 有 CSRF token；用户名错误会触发验证码 |
| 分站 | 31 个省级分站全部解析到同一台服务器 |

这些结论的用途是**理解这个平台**，项目里已经不包含任何登录代码。

---

## 如果你想自己实现自动化

本项目**不提供**这条路，但你可以基于运行观测到的行为自行实现。
需要注意：

- 平台的批量录入接口可能变化，需自行跟踪
- 自动操作前建议先用一两条测试数据验证
- 请确认你的操作符合所在单位和服务平台的规定

## 附：沙箱环境的技术限制（如果你在受限环境里开发）

供参考，与本项目主功能无关：

| 操作 | 结果 |
|---|---|
| `spawn` 且 `stdio: 'inherit'` | 正常 |
| `spawn` 且 `stdio: 'pipe'` | `EPERM` |
| 通过管道捕获子进程输出 | 被禁止 |

浏览器驱动必须通过管道与浏览器通信，因此在禁止管道的环境里必然失败。
这也是本项目最终确定「不驱动浏览器」的一个现实原因。
